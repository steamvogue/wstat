# wstat v0.1.1

This patch release fixes performance and monitoring-correctness problems found
in the project review. PHP access requests now appear only in Services, so the
same request in web and PHP logs no longer doubles web requests or treats PHP
memory as network traffic.

## Changes

- Select displayed rows with bounded top-K heaps, cache unchanged snapshots and
  honor Go's `GOMEMLIMIT` instead of forcing a 48 MiB limit.
- Replace old URL/client detail at capacity, bound hosts and client/host
  associations, expose eviction counters and preserve selected rows on refresh.
- Calculate exact joint status/bot/static metrics on supported dimensions.
- Preserve partial lines and descriptors across seed/follow and rename/recreate;
  follow extensionless and empty log paths with bounded replay and diagnostics.
- Read slowlogs incrementally and probe FPM asynchronously with cancellation.
- Parse configured PHP duration/memory units, show separate service measurements
  and correct `/proc` RSS units and malformed-field handling.
- Report invalid config, validate edited files, retain explicit zero/false values,
  honor cache/FPM controls and vhost pins, and invalidate included-config changes.
- Add opt-in CPU/heap profiles and reusable benchmarks/workload diagnostics;
  remove unused tailing dependencies.

## Measurements and limits

On the controlled Raspberry Pi 5 workload with 54,000 seed requests, 63 files and
a 500 ms dashboard refresh, idle CPU fell from 16.4% to 2.8%; at 100 requests/s it
fell from 18.1% to 4.7%. Snapshot rebuild allocation fell about 99.5%.
Peak RSS increased from roughly 53–54 MiB to 72–78 MiB. These are short fixture
measurements, not universal resource guarantees or verification of the original
200% CPU incident.

Local regression tests, static build, vet, lint and formatting pass. The local
ARM64 race detector cannot execute because of its virtual-address layout; release
publication requires successful Ubuntu CI, including the race suite. Controlled
FastCGI fixtures pass; disposable real-PHP-FPM E2E remains optional and was skipped.
Concurrent copytruncate has an inherent unread-data loss window. Evicted table
detail is partial even though global web totals continue counting.

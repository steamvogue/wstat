# wstat v0.2.0

This release makes dashboard navigation more stable and adds independent Hosts
freeze plus navigation in the Services panes.

## New controls

- **`F` (Shift+f):** freeze/resume Hosts rows and values. A `[frozen]` marker
  appears; ingestion and other panes continue updating.
- **`f`:** pause stream auto-follow; press again to jump to the latest visible
  request and resume. `Up` / `g` stops follow; `G` or Down to the end resumes it
  unless `f` is active.
- **Services:** Tab / Shift+Tab cycles pools, sources and stream. `1` selects
  pools, `2` sources, and `3` / `4` the stream. Arrows / `j/k`, `g/G`, search and
  zoom now work in these panes, with separate table selections and zoom state.

## Fixes

- Keep compact key hints on the bottom row and include the view switch.
- Apply filters/sorts immediately and return affected tables to the top;
  monitoring at row zero keeps live leaders visible.
- Follow the same request when scrolling through incoming traffic, including
  identical requests; navigation and rendering use the same search matches.
- Keep search scoped to the selected pane, preserve other pane positions,
  remove whole UTF-8 characters on backspace and clamp empty selections.
- Correct bordered panel sizing so selected rows and the latest request stay
  visible across resizing and zoom.
- Document and verify existing `TERM=xterm-256color` support.

## Behaviour to know

Changing the Hosts sort, status/bot/static filters, or clearing filters resumes
Hosts updates. The recent stream snapshot contains at most 100 records matching
the global filters; if a selected request expires, selection falls back to the
oldest visible record. At minimum terminal heights, zoom provides room to read
panels that otherwise show only a title.

## Validation

Local full Go tests, vet and lint, formatting and workflow validation passed.
Both static Linux architectures build with version wiring. The regression
suite covers filter scopes, all
dashboard panes, search/cancel/empty results, reorder, stream rollover,
duplicates/expiry, freeze/resume, resize/zoom, real source fixtures and Services
navigation. The compiled Linux/ARM64 CLI passed a PTY smoke check with 54,000
seeded requests and 299 live records emitted; the final sentinel was visible and
the process exited normally. Indexed 256-colour output was verified.

The final checks also exposed a timing race in the fake FastCGI server: it
answered at the PARAMS terminator before the client finished STDIN. The fixture
now waits for complete request input before responding; the corrected roundtrip
passed 100 consecutive repetitions.

See [scrolling review and use cases](../implementation/scrolling-review.md) and
[keymap](../../README.md#keymap). The GitHub release notes include the successful
CI run (with race tests), release workflow and published artifact verification.
